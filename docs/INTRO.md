# 项目介绍 · 为什么要做 Code-2-Video-Lab

## 一个问题

2026 年，用代码生成视频这件事已经不再稀奇。一个提示词能换来一条 30 秒的片子，一个开源框架能把 HTML 渲染成 MP4，一个 agent 能在几小时里跑完分镜、素材、剪辑、混音。工具在快速变好，但**判断力没有跟着变好**。

真正让人卡住的不是「能不能做出来」，而是这些问题：

- 同一句提示词，两个模型差 1.76 倍价钱，快的那条反而更贵——这种反直觉的事实，藏在一条几百字的推文里。
- 一个 README 说「10 分钟出片」，但没说那 10 分钟是生成时间，还是含返工的端到端时间。
- 131 个 agent、101 亿 token 做出 5 分 26 秒，这组数字很震撼，但它是不是能当成基准？不能，因为任务不可比。
- 一个框架的 LICENSE 是 Apache-2.0，但它的官方样片能不能被转载？这从来不是同一件事。

这些信息并不缺，它们散在 GitHub、X、飞书文档、公众号里。缺的是**把它们放在同一个口径下、并且标清楚每个数字是谁说的**。

Code-2-Video-Lab 就是为这件事做的。

## 它是什么

一个静态的中文内容站，把「代码生成画面」这条链路上的四类东西放进同一个展厅：

1. **项目**——开源的代码视频工具与框架。看的是技术路线差异：React 按帧、单文件 `frame(t)`、HTML + 无头浏览器、Rust/GPU、Blender + Python。
2. **网页案例**——100 个单文件 HTML 页面。它们不是视频，但它们证明了一件事：一段代码能直接长出可交互的视觉，不需要渲染农场。这是「代码即画面」这条光谱的另一端。
3. **创作作品**——真实做出来的 AI 视频，附作者披露的制作细节：几小时、多少钱、什么设置、有没有对比版本。
4. **案例精读**——24 个「能算账」的案例。每一个都能回答：花了多久、多少钱、消耗多少额度或 token、用什么链路做出来的。

四种条目用同一套行业分类、同一套技术栈标签、同一套筛选。找到什么，取决于你想问什么。

## 三个设计决定

**第一，证据比内容重要。**

大多数项目集合只回答「这个项目是干什么的」。这里每一条还要回答「我凭什么这么说」。所以每个详情页都有：

- 来源核验说明：读了什么、没读什么、有没有跑过。
- 代码许可与媒体使用依据，分成两张表，互不推导。
- 精读页额外有「来源与证据缺口」：作者没说的，逐条写「未说明」。

这不是为了显得严谨，是因为**这个领域最常见的错误就是把个案当基准**。一条 25 秒的对照实验被转成了「某模型贵 1.76 倍」的行业结论，中间丢掉的正是「同场景、同分辨率、未含重试」这些前提。

**第二，预览不能是装饰。**

一个视频项目的详情页，如果主视觉是一张精心挑选的封面图，那和海报没区别。所以：

- 有原视频的，放 5 秒静音循环，点进去就在动（57 个条目）。
- 网页案例不是录像，是真的能运行——点一下，原作者托管的页面在沙箱 iframe 里加载，你可以直接玩。
- 没有可用原片的，宁可保持静帧，也不用一段对不上的视频充数。有两例的原帖视频是同一串帖的共用片头，主题对不上，就直接不放。

**第三，门禁写进代码。**

「不写实测」「许可不能推导」「每段素材都要有独立来源」这些规则，如果只写在文档里，第三次更新就会忘。所以它们被写成了 `scripts/validate.mjs`：

- 必填字段缺失、资产不存在、首条媒体登记和封面不一致、出现肯定式实测措辞——**构建失败**。
- 第三方外链打不开——**不阻断**，写进人工复核清单，区分「确认异常」和「本环境无法判定」。

一个内容站的可信度，取决于它在没人盯着的时候会不会放水。

## 它不是什么

- **不是视频生成工具**，没有模型调用，没有渲染管线。
- **不是排行榜**，不做跨案例的成本排名，因为任务不可比。
- **不是自动爬虫**，内容人工维护，最后一次整理是 2026-11-16。
- **不是完整收录**，631 条合集里只挑了 31 条作品、24 条精读，标准是「有真实预览 + 来源完整 + 路线有差异」。

## 后面

这个站目前是「看清现状」，下一步更想做「可复现」：给每个项目补一份 manifest（commit、引擎版本、seed、参数、产物），让「这条片子是怎么来的」不只可读，还能重跑。

在那之前，先把已经公开的东西整理到能看懂、能追溯、能判断——这本身就有价值。
