看哪里

看哪里。看人物线条的抖动与色块边缘——这是“逐帧渲染 + 手绘笔触 pass”的痕迹，不是视频模型插帧的平滑感。

链路拆解

核心定位用超长提示词锁定画风与工艺：明确排除 3D 与视频模型，指定 three.js + headless Chrome + ffmpeg。
适用场景要“像动画电影”的手绘质感、且不接受视频模型的团队。
必备输入3,492 字符提示词（公开）；three.js（WebGL2）、Chrome headless 逐帧渲染、ffmpeg 编码；管弦配乐。
标准流程提示词锁定风格与工艺 → 六个部门（城市、天空等）并行产出 → headless 逐帧渲染 → ffmpeg 编码为 1920×1080 / 24fps。
AI职责画面、渲染脚本、编码参数全部由模型决定；人给提示词与验收。
关键指标目标：78 秒 1080p24 成片。实际：六个并行部门、14.2K 播放；模型归属为作者自述的 Fable 5.5，未独立复现。

为什么值得看

这份提示词最硬的部分是“禁止项”。它明确写了不要 3D 动画、不要动态插画、不要网页风格图形，并且指定在浏览器里用 WebGL2 逐帧渲染、加一层手绘笔触 pass 和一层墨水 pass、最后用 ffmpeg 编码。这已经不是审美描述，而是工艺规范——模型拿到的是可执行参数，不是形容词。

为什么值得把提示词写到三千字。因为“像日本动画”这句话本身不可执行。拆到渲染层之后，判断标准变成了分辨率、帧率、笔触层数、编码器，人可以逐项验收，模型也可以逐项对齐。这是把主观要求转成可检查对象的标准动作。

六个部门并行，说明它复用了同一套镜头契约。城市、天空等部门各自产出，但共享同一套画风与相机规范。这套规范藏在提示词里，也是它能被复用的部分。

可复用点与适用边界

可以迁移的

把“像某种风格”改写成“用什么渲染、几层 pass、什么编码”，是可复用的提示词结构。

成立的条件

团队要能接受逐帧渲染的等待，并具备 headless 渲染环境。

不能外推的

复杂角色表演与长镜头调度仍需人工介入；78 秒是短片尺度。
