ATTENTION IS ALL YOU NEED：131 个 agent、101 亿 token 做出 5 分 26 秒

片长一旦超过 3 分钟，瓶颈就从“生成”变成“编排”——这条案例把编排开销第一次量化到了 token 级。

看哪里

看哪里。看片头标题卡：S1-01、A LECTURE IN 96 LAYERS，以及底部 <|endoftext|> 50256 的字幕——这是模型给自己写的元叙事，说明编排层在控制叙事结构，不只是堆画面。

链路拆解

核心定位把长片当工程调度：131 个 agent 分部门并行，用一个 token 总量衡量整条产线的规模。
适用场景有清晰词曲或分镜结构、可以拆成并行工段的长片、MV、纪录片式内容。
必备输入人写的钢琴旋律与歌词；外部素材模型（Grok Imagine Image 2.0 / Video 1.5、Qwen-Image 2.1）；Suno 音乐；Blender 承担 3D 段落。
标准流程词曲 → 分镜 → 131 个 agent 按部门并行生产素材 → Blender 段落地制作 → 统一剪辑与混音。
AI职责分镜、素材生成、3D、字幕、剪辑决策由 agent 承担；人负责作曲、歌词与终审。
关键指标目标：5 分 26 秒纪录片式 MV。实际：26 小时 51 分、10.1B token、23,354 次模型调用、131 个 agent（均为作者自述）。美元成本未披露。

为什么值得看

10.1B token 这个数字，比“131 个 agent”更值得记。如果把 token 当成产线的“耗材”，这条片子相当于烧掉了 101 亿个 token 才换来 5 分 26 秒。23,354 次模型调用除以 131 个 agent，平均每个 agent 调用约 178 次——真正的工作量不在单次生成，而在反复的调度与重试。这也解释了为什么长片的时间成本是超线性的。

链路是混合的，不是纯代码。作者的清单里同时出现了 Grok Imagine 的图像与视频模型、Qwen-Image、Suno 和 Blender。这不是“代码生成视频”的原教旨做法，而是把视频模型当素材供应商、把代码当编排层。判断这类项目时，看的是编排层能不能稳定调度异构工具，而不是它有没有用到视频模型。

人留下的那部分，恰好是最难被替代的。钢琴旋律由作者写、歌词由作者写，模型负责把它变成 96 层结构的影像。这条分工线很清楚：可结构化的部分交给 agent，需要作者性的部分留在人手上。

可复用点与适用边界

可以迁移的

长片按“部门”拆 agent（画面、音乐、字幕、剪辑），而不是按镜头拆——按镜头拆会让 agent 数量爆炸而协作成本失控。

成立的条件

需要一个能记录调用次数的编排层，否则连“花了多少”都无从统计。

不能外推的

只有 token 总量、没有单价与账单，无法换算成钱；也无提示词与 runlog，不可复现。
